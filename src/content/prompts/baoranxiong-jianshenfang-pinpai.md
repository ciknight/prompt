\#【核心架构规范】使用 JSON Bridge 模式

为避免语言环境切换导致中文乱码，必须按以下稳定流程执行，不得自行改线：

1. 阶段 1 必须直接使用内置 image gen / Images 2\.0 生成非文字元素白底图。
2. Python 仅负责本地透明化、OCR、校验，并将后续合成所需信息统一写入 UTF\-8 编码的 manifest\.json。
3. manifest\.json 至少包含：图层名称、图片路径、绝对坐标、绝对尺寸、真实 Unicode 文本、字号、颜色等。
4. Node\.js 只读取 manifest\.json 合成最终 PSD。
5. 绝对禁止在 PowerShell 参数、管道或内联脚本字符串中直接传递中文字符串。

\#【执行顺序】

- 第一阶段只能生成“非文字元素白底图”
- 第二阶段才能透明化、OCR、重建文字和合成 PSD。
- 不要跳过第一阶段；不要在第一阶段之前做 OCR、PSD 合成，或检查 OPENAI API KEY、OpenAI SDK、CLI fallback、本地 API 能力。
- 当前环境已有内置 image gen / Images 2\.0 能力，必须直接使用；如果不能直接调用，就停止并说明“无法执行阶段 1”，不要使用替代方案。

<a id="heading_13"></a>__阶段 1：非文字元素白底图生成__

<a id="heading_14"></a>__1\. 元素拆分逻辑__

先列出主要非文字视觉元素（10 个以内，不能重复，字属小拆也不乱拆，同构阵列/对称/列表/规律重复组件当成一个整体元素，难拆细小元素融入背景图），包含但不限于：

背景、主体、前景、Logo（内部不再拆分）、图标（对称/规律/阵列当成一个整体）、徽章、边框、光效等。

注：

- Logo、商标、字标属图像元素，必须留在本阶段，禁止交给 OCR。
- 只要有独立移动价值的元素就应尽量单独生成，勿为减图层而合并。

<a id="heading_15"></a>__2\. 生成规范（严禁作弊）__

- 背景层：生成一张保持原画布尺寸、光影与构图的完整背景层（不含可编辑文字）。
- 白底元素图：对可独立移动的非文字元素，必须使用内置 image gen / Images 2\.0 执行原位隔离编辑。

目标不是重新创作一个相似元素，而是：

- 以原图作为唯一几何基准；
- 尽量原位保留目标元素的版面位置、外接占位范围、视觉中心、关键锚点、大小比例、透视方向和朝向；
- 将除目标元素以外的所有区域改为纯白背景；
- 输出仍然是与原图同尺寸的蛤蜊画布；
- 如果当前 image gen 调用路径支持“高输入保真 / high input fidelity / 高保真编辑”，必须优先启用，以提高目标元素与原图之间的位置和形态一致性。
- 除目标元素外改为纯白背景，输出整张同尺寸画布，不得裁成小图再贴回。
- 不允许用本地遮罩、OpenCV、Pillow、抠图或原图切片代替 image gen 做元素分层。
- 阶段 1 可接受 2%–4% 的轻微画幅误差；整体位置 / 大小误差约 10% 内。

<a id="heading_16"></a>__3\. 阶段 1 检查__

检查：是否纯白背景、是否仅含单一目标元素、尺寸与原图是否基本一致、绝对位置是否匹配、是否存在明显重绘 / 漂移 / 缩放 / 错位 / 混层。

检查通过后方可进入阶段 2。若少于 5 张图未通过，可额外重试 1 次；仍不通过则停止。

<a id="heading_17"></a>__阶段 2：透明化、文字重建和 PSD 合成__

<a id="heading_18"></a>__一、画布与透明化__

所有中间图、透明图、SVG 定位和最终 PSD 都必须统一回原图绝对画布尺寸及坐标。

对阶段 1 的白底图只做本地透明化、尺寸校验、辅助处理与 PSD 合成；不得把本地处理当作元素分层来源。

白色主体保护规则：

- 不得简单按“接近白色就删除”。
- 只移除与画布边缘连通的纯白背景区域。
- 主体内部白色、浅色高光、白色包装、浅色布料、蒸汽、烟雾、半透明边缘等不得被误删。
- 稀疏元素层透明化后，画布大部分必须真的变成 alpha=0
- 若透明化导致主体被掏空、发灰、出现错误透明洞、白边或边缘污染，必须先修正，再继续合成。

<a id="heading_19"></a>__二、文字重建与 manifest\.json__

对原图文字进行 OCR（不包含 logo 内文字）。

- 每一行文字都必须先重建为 SVG 中独立的 <text> 节点，再写入 PSD 中独立的可编辑 Type Layer。
- 文字不得转成路径或图片；栅格预览层不能替代可编辑文字层。
- 每行文字都必须在 SVG 与 PSD 中使用可追踪命名：文字 类型 具体内容。
- OCR、SVG、脚本、manifest\.json 等都必须保存真实 Unicode（UTF\-8）。
- 严禁出现 ?、乱码、方框、mojibake、缺字或错误替代字符；一旦出现，立即终止文字流程，不得继续合成。
- 文字层尽量匹配原图中的位置、字号、颜色、字重、行距、方向和对齐方式。

<a id="heading_20"></a>__三、PSD 合成__

- PSD 底层为完整背景层，其上依次放置透明化后的非文字元素层与文字层。
- 所有图层保持原图绝对坐标。
- 所有图层名称必须使用简体中文；非文字层直接按内容命名，文字层必须使用 文字 类型 具体内容。
- PSD 必须能在 Photoshop 中正常打开。

<a id="heading_21"></a>__最终自检__

交付前确认：

- PSD 尺寸与原图一致；
- 包含背景层、多个非文字元素层、每行独立的可编辑文字层；
- SVG 中每一行 <text> 与 PSD 文字层可一一对应；
- 不存在乱码、替代字符、栅格文字冒充 Type Layer；
- 透明化后无主体误删、白边或明显边缘污染；
- 所有中间文件均已整合进 PSD；
